# 프로젝트 스튜디오 구조

프로젝트 → 원본 음악(최대 3개) → 분리 스템 → 선택 보컬 분석과 리포트 순서로 구성한다. 사이드바는 프로젝트와 스튜디오만 두고, 원본은 스튜디오 상단 탭으로 전환한다. 일반 모드는 측정 요약, 고급 모드는 시간 그래프·스펙트로그램·프로젝트 보컬 비교를 제공한다.

## 구현 파일

- `auth.py`: Gmail 주소/비밀번호 인증, 환경변수 관리자, 서버 세션, 프로젝트 소유권 검사. 내부 사용자 UUID는 향후 Discord 연결에도 재사용한다.
- `i18n.py` / `static/i18n.js` / `static/locales/en.json`: 공통 한영 번역, 브라우저 언어 쿠키, 화면·오류·상태 메시지와 숫자/이름 보간. 리포트 작업은 제출 언어를 저장하고 언어별로 중복을 판별한다.
- `main.py`: 원본/스템 API, 단일 백그라운드 작업 큐, 분석·분리·리포트·파일 생명주기.
- `project.py`: 이전 독립 보컬 트랙을 원본+하위 보컬 구조로 호환 변환.
- `separation.py`: FFmpeg 44.1kHz 스테레오 디코딩, Demucs 모델 로드·추론, NumPy 실제 파형.
- `audio.py`: 모노 22.05kHz 변환, pYIN·RMS·STFT, 키/속도 변형과 PCM 분석 캐시.
- `report_queue.py`: 서버 전체의 영속 리포트 FIFO, 중복 요청 통합, 공유 진행 상태와 재시작 복구.
- `ai_provider.py`: 독립 AUDIO/LLM 설정, OpenAI 호환 HTTPX 요청, /models 확인, 안전한 오류 처리.
- `music_ai.py`: 원본·보컬의 오프셋 적용 구간을 WAV로 나눠 실제 청취 요청, 구간/해시/관찰 기록.
- `backend/check_ai.py`: 실제 짧은 음악 WAV로 두 API를 검증하는 CLI.
- `reports.py` / `markdown.py`: 구간 측정 근거, Flamingo 관찰과 DSP를 종합하는 gpt-oss 보고서, Markdown 렌더링과 HTML 정제.
- `database.py`: MongoDB / OpenSSH 터널, 접속 정보가 없을 때 명시적인 로컬 JSON 미리보기.
- `ui.py` / `templates/`: Jinja 서버 렌더링과 음원별 스템 HTML 조각 갱신.
- `static/app.js`, `player.js`, `charts.js`: 일반 ES 모듈 이벤트, 스템 동시 재생, 실제 데이터 Canvas 그래프.
- `static/app.css`, `static/reference/`: UnivDash 기반 레이아웃·설정·테마·폰트.

FastAPI 서버 하나가 HTML·정적 자산·API를 모두 제공한다. Node/React/TSX/프론트 빌드는 필요 없다.

## 데이터 흐름

원본 업로드 → 크기/확장자 검사 → 무작위 ID 저장 → FFmpeg 디코딩과 길이 검사 → Demucs 실제 분리 → 스템 WAV와 파형 저장 → 사용자가 분석 활성화 → 분리 보컬의 NumPy/librosa 분석 → 요약·그래프 → 측정 리포트 또는 AI 평가.

프로젝트의 `tracks`는 원본 음악이며, 각 원본의 `stems`가 분리 트랙과 파생 보컬을 보관한다. 각 원본은 독립적인 분리 상태와 작업 ID를 갖고 각 보컬은 독립적인 분석 상태·결과 캐시를 갖는다. 분리 완료만으로 보컬 측정을 자동 실행하지 않는다. 파생 보컬은 원본 3개 제한을 차지하지 않고 음원당 전체 트랙 수는 12개로 제한한다.

업로드 원본은 `uploads/`, 믹서 재생용 스테레오와 스템은 `audio/`, 큰 분석 JSON은 `cache/`, 공식 모델 가중치는 `models/`에 둔다. 프로젝트·파형·요약·최근 리포트 10개는 MongoDB 또는 명시적인 로컬 미리보기 JSON에 저장한다. 다른 PC에서 같은 DB를 사용해도 로컬 파일은 자동 복제되지 않는다.

재분리는 임시 출력 디렉터리에서 완료한 뒤 메타데이터를 교체한다. 실패하면 기존 재생 파일을 유지하며 오류와 재시도를 표시한다. 원본 삭제는 해당 원본의 모든 스템·변형·측정 결과·관련 리포트를 함께 정리한다. 이전 보컬 형식은 기존 파일/요약을 유지하고 `legacy` 상태로 구분한다.

분석 캐시는 엔진 버전과 실제 디코딩 PCM SHA-256을 사용한다. 변형은 원본 보컬을 보존하고 새 WAV를 분석한다. 리포트는 선택 보컬 또는 프로젝트의 분석 완료된 기본 보컬들을 대상으로 한다. 고급 모드의 오프셋은 프로젝트 보컬 비교/리포트의 수동 시간 정렬에 적용하고, 선택 음원의 악기·보컬 재생은 같은 타임라인을 공유한다.

Markdown은 서버에서 제목·표·목록·인용·코드·링크를 렌더링한다. 원시 HTML과 실행 가능한 링크는 정제하며, 저장된 이전 리포트도 다시 렌더링한다. AI 요청은 AUDIO_* Music Flamingo에 실제 선택 구간의 원본 믹스·보컬 WAV를 전송하고, LLM_* gpt-oss-120b에 Flamingo 관찰·측정 JSON·파일명을 전송한다. API URL/모델/키는 .env의 AUDIO_AI_* 및 LLM_AI_* 그룹에서 독립 관리하고 프론트엔드에는 모델명과 설정 여부만 제공한다. 두 서버의 /models ID를 매 작업마다 확인하며 실제 input_audio 요청 성공 전에는 오디오 호환성을 검증했다고 표시하지 않는다.

## 모델과 측정 해석

Demucs 기본 `htdemucs`는 보컬·드럼·베이스·기타 반주 4스템이다. `htdemucs_6s`는 기타·피아노를 추가하며 실험적이다. 자동 디바이스는 CUDA가 사용 가능하면 GPU, 그 외 CPU다. 공식 가중치를 첫 사용 시 다운로드하고 재사용한다. 허용된 공식 모델 이름만 로드하며 사용자 체크포인트 업로드는 받지 않는다.

pYIN은 CPU 확률 기반 F0 추정이다. 음역은 유효 음정의 P5–P95, 다이내믹은 활성 프레임 RMS dB의 P95−P10이다. 음 중심 편차는 평균율 음까지의 거리이며 악보 대비 정확도가 아니다. BPM·비브라토는 후보, 주파수 중심·평탄도는 음향 지표다. 발성 유형이나 가창 순위를 확정하지 않는다. 분리 누설·잔향은 측정 오차를 늘릴 수 있다.

## 운영 한계와 검증

여러 사용자 계정을 단일 서버 프로세스에서 처리한다. 단일 워커가 작업을 순서대로 실행한다. 분리/수치 분석 큐는 메모리 기반이고 재시작 시 미완료 작업을 실패로 표시한다. 리포트 작업은 MongoDB `report_jobs` 또는 로컬 `jobs/`에 상태·측정 근거 스냅샷·결과를 영속 저장한다. 재시작 시 처리 중이던 요청은 실패 처리하고 실행 전 대기 요청은 FIFO로 복원한다. 두 제공자의 URL/모델/키 또는 청취·토큰 설정이 바뀌면 해당 대기 요청은 실패한다. 분산 작업 큐·자동 음악적 정렬·샘플 단위 재생 동기화는 포함하지 않는다. 브라우저 HTMLAudio 타임라인으로 동기 재생하며 긴 음원에서 보정 오차가 생길 수 있다.

단위/API 테스트는 합성 신호 DSP, 프로젝트 3개 원본 제한, 중첩 스템과 변형, 분석 캐시, 비교·삭제, Markdown 정제와 이전 데이터 호환을 검증한다. API의 모델 추론은 테스트 대체 구현이고, 실제 모델 추론은 별도 합성 신호로 확인했다. 실제 가수 녹음 품질, 실제 SSH/Mongo 연결과 외부 AI 호출은 각각 음원·접속 정보·제공자 설정 후 추가 검증이 필요하다.

## 공유 AI 진행 상태와 요청 제어

`GET /api/report-jobs`는 로그인한 계정의 실행/대기 목록, 대기 순번과 최근 완료/실패 메타데이터를 반환한다. 모든 페이지의 공통 패널과 음원 안 리포트가 같은 서버 상태를 2초마다 조회한다. 페이지의 로컬 작업 ID나 브라우저 저장소가 실행 여부를 결정하지 않는다. `GET /api/jobs/{id}`로 완료 결과를 다시 가져오며 Markdown을 서버에서 재정제한다.

`POST /api/projects/{id}/reports`의 `enqueue`는 기본 false다. 서버가 바쁘면 다른 즉시 요청은 409, `enqueue=true`는 최대 20개까지 명시적 대기 요청으로 받는다. 동일한 미완료 요청은 측정 근거/범위/모델/제공자의 해시로 통합해 기존 작업 ID를 돌려준다. 접수와 프로젝트 변경은 같은 서버 잠금 안에서 처리한다. 대기 중인 프로젝트의 삭제/재분리는 막고, 삭제 또는 재분리가 완료되면 관련 작업 이력도 정리한다. 외부 AI 실패는 해당 작업만 실패 처리해 다음 순서를 막지 않는다.

단일 FastAPI 프로세스를 전제로 하며 여러 서버/워커 간 분산 잠금은 제공하지 않는다. 독립 클라이언트의 공유 조회·동시 중복 요청·직접 접수 거부·순차 실행·실패 복구·대기열 영속 저장을 테스트한다.


## 실제 음악 AI 통합

리포트 접수는 202를 반환하고 기존 영속 FIFO 워커가 Music Flamingo 청취 → gpt-oss 해석을 실행한다. 네트워크 요청은 백엔드 워커에서만 처리하므로 FastAPI 요청 처리를 막지 않으며 브라우저를 닫아도 계속된다. 업로드 시 외부 AI를 자동 호출하지 않고 사용자가 AI 분석으로 전송을 시작한다.

측정 근거와 오프셋 적용 구간/파일 참조를 접수 시 스냅샷으로 보관한다. 원본과 기본 보컬을 각각 청취하고, 시간축이 달라질 수 있는 변형본은 그 보컬만 청취한다. WAV 변환은 모노 24kHz PCM16이며 음량 정규화 없이 디코딩한다. 기본 30초 이하로 고르게 나눠 선택 구간의 모든 프레임을 보낸다. 각 응답마다 관찰, 원본 프레임/시각, WAV 해시, 변환 형식, 클리핑 표본 수, 응답 ID와 사용량을 보관하며 Base64 데이터는 보관하지 않는다. 실제 클리핑과 분리 아티팩트는 해석의 한계다.

Flamingo 관찰은 측정 사실과 구분해서 최종 LLM에 전달한다. DSP와 청취 해석의 충돌은 검토 대상으로 드러내고 전문가 의견을 만들어 넣지 않는다. expert_feedback는 아직 빈 목록이며 검토·학습 시스템과 실제 파인튜닝은 다음 단계다. 완료 리포트 10개는 프로젝트에도 표시하고 전체 작업은 report_jobs에 남는다. 프로젝트/음원 삭제 시 관련 작업도 삭제되므로 영구 학습 코퍼스 보관이나 학습 자동 실행을 의미하지 않는다.

LLM 실패 시 부분 청취 결과는 GET /api/jobs/{id}의 partial_audio_analyses와 저장된 작업에 남고 최종 성공 보고서로 표시하지 않는다. 서버 재시작 중단은 기존 복구 규칙을 따른다. 설정만으로 연결 성공을 표시하지 않으며 실제 서버 검증 절차와 이번 검증 범위는 [ai-validation.md](ai-validation.md)에 기록한다.
