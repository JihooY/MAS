# 구현 구조와 다음 단계

## 이번 범위

사용자의 직접 요청에 따라 첨부 문서의 Phase 1 분리/4스템 기능보다 **보컬 비교·변형·측정·AI 해석**을 우선했다. 악기 분석과 음원 분리는 포함하지 않는다.

```
frontend/src/
  App.tsx          프로젝트 · 비교 워크플로 · 동기 재생
  components.tsx   모달 · 파형 · 그래프 · 스펙트로그램 · 테마
  api.ts           서버 API
  types.ts         데이터 계약
  styles.css       UnivDash 기반 반응형 레이아웃
frontend/public/reference/   UnivDash 테마 CSS와 폰트
backend/app/
  config.py        .env 설정
  database.py      OpenSSH 터널 · MongoDB / 명시적 로컬 미리보기 저장
  audio.py         디코딩 · 변형 · pYIN · RMS · STFT · 캐시
  reports.py       구간 측정 근거 · 제공자 교체 가능한 LLM 해석
  main.py          API · 작업 큐 · 파일 생명주기
tests/             실신호 DSP 테스트 · API 통합 · Mongo 저장 계약
storage/           원본 · 분석용 WAV · 캐시 · 로컬 미리보기 메타데이터 (Git 제외)
```

## 데이터 흐름

업로드 → 크기/확장자 검사 → 무작위 ID 경로 저장 → 단일 백그라운드 워커 → 길이/채널/샘플레이트 검사 → 모노 22.05kHz PCM → NumPy/librosa 분석 → JSON 캐시 → 그래프.

키와 속도 변형은 독립적으로 적용하고 변형본을 새 슬롯에 저장한다. 분석은 변형된 PCM을 대상으로 다시 수행한다. 정규화는 선택한 경우 피크 0.95로 적용한다. 재생 음량 매칭은 원본을 바꾸지 않고 RMS 기준 감쇠만 한다.

분석 캐시는 엔진 버전과 디코딩된 PCM 샘플의 SHA-256을 키로 사용한다. MongoDB에는 프로젝트와 트랙 요약, 최근 리포트 10개를 저장한다. 큰 시계열/스펙트로그램 및 음원은 로컬 저장소에 둔다. 프로젝트와 로컬 저장소는 같은 서버에서 관리해야 한다.

## 분석의 의미

- pYIN은 확률 기반 F0 추정이다. 현재 DSP 엔진은 CPU이며 GPU 신경망 추론으로 표시하지 않는다.
- 음역은 유효 음정의 5–95 백분위이다.
- 음 중심 편차는 가장 가까운 평균율 반음과의 거리다. 악보 대비 정확도/안정성 점수가 아니다.
- 다이내믹 범위는 활성 프레임 RMS dB의 P95−P10이다. LUFS/EBU R128 측정이 아니다.
- 주파수 중심·스펙트럼 평탄도는 음향 특징이다. 기식성이나 발성 유형을 확정하지 않는다.
- 비브라토 후보는 1.5초 이상 연속 유성음에서 4–9Hz 대역 주기성이 우세할 때 제시한다. 분류 모델이 아니다.
- BPM은 보컬 강세에서 추정하는 주기 후보다. 곡 템포로 확정하지 않는다.
- LLM은 요약 수치만 전달받고 직접 듣지 않는다. AI 결과의 사실성은 사람 검토가 필요하다.

## 현재 운영 한계

로컬 단일 사용자/단일 서버 프로세스를 대상으로 한다. 사용자 인증, 원격 공개 서비스, 다중 워커, 분산 큐는 구현 범위에 없다. 로컬 호스트와 같은 출처만 허용한다. 브라우저의 HTMLAudio 타임라인을 공유하므로 샘플 단위 동기화와 음악적 구조 정렬은 제공하지 않는다. 분석은 20초 블록 단위이며 경계 오차가 있을 수 있다. 서버 재시작 시 진행 중 트랙은 실패로 표시하고 재시도를 제공한다. 작업 큐 자체는 메모리에 있다.

## 다음 확장

1. 실제 분리 보컬/여러 가수에 대한 F0와 비브라토 후보 검증, 주석 데이터와 비교.
2. 신경망 F0 모델(CREPE 등)과 검증된 모델별 신뢰도, GPU 선택.
3. Redis 기반 내구성 작업 큐, 취소, 프로젝트별 잠금/다중 사용자 인증.
4. DTW 등 음악적 구간 정렬과 참조 멜로디 대비 분석. 수동 오프셋과 구분해 제공.
5. 별도 분리 모듈 및 모델 라이선스 확인 후 보컬 준비 워크플로 연결.
6. Web Audio AudioWorklet 기반 샘플 동기화와 실시간 독립 키/속도 처리.
